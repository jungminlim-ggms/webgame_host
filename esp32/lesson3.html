02 · DESIGN THE STATE

입력은 같아도, 기억은 다를 수 있어요.

7분

버튼을 놓으면 입력은 HIGH(1)입니다. 하지만 요청은 켜져 있거나 꺼져 있을 수 있어요. 그 차이를 requestOn이라는 변수에 저장합니다.

요청 없음requestOn = false · LED 꺼짐
새로 누르면 →
← 다시 누르면
요청 중requestOn = true · LED 켜짐

놓기와 계속 누르고 있기에서는 현재 요청 상태를 유지합니다. 전원 재연결·보드 리셋 시에는 요청 없음으로 시작합니다. 전원을 꺼도 저장되는 기억은 아닙니다.

2차시와 3차시, 같은 입력으로 비교하기

화면 속 논리 모형

입력 HIGH(1) · LED 꺼짐

3차시 · 요청 상태를 기억

requestOn = false · LED 꺼짐

버튼 놓음 · 새 누름 0회

‘누르기’를 선택하면 ‘놓기’를 선택할 때까지 눌린 상태가 유지됩니다. 기다려도 요청은 다시 바뀌지 않아요. 이 모형은 안정적으로 인식된 입력을 가정하며 실제 버튼 튐과 50 ms 판정 시간을 재현하지 않습니다. 아래에는 최근 8개 동작이 표시됩니다.

03 · CONNECT & RUN

회로는 그대로, 코드에 기억을 더해요.

10분
회로를 바꿀 때는 USB를 분리하세요. 2차시와 같은 GPIO 18 버튼, GPIO 23 LED, 330 Ω 저항을 사용합니다. 새로운 부품은 필요하지 않습니다. 버튼 접점과 공통 GND를 먼저 확인하세요.

2차시 브레드보드 연결 지도 ↗

입력GPIO 18 ↔ 버튼 ↔ GNDINPUT_PULLUP · 누르면 LOW
→
처리새 누름 → 상태 반전requestOn = !requestOn
→
출력GPIO 23 → 저항 → LEDLED − → GND로 연결

학생이 설명할 핵심 부분

if (previousStable == HIGH &&
    stableButton == LOW) {
  requestOn = !requestOn;
}

HIGH → LOW로 바뀐 순간만 새 누름으로 인정합니다. !는 true를 false로, false를 true로 뒤집습니다.

requestOn을 loop 안에서 매번 false로 초기화하면 이전 요청을 기억할 수 없어요. 전체 코드에서는 함수 밖에 선언합니다.

선생님이 제공하는 버튼 튐 처리

실제 버튼은 한 번 눌러도 접점이 짧게 흔들릴 수 있어요. 아래 코드는 원래 입력이 바뀐 뒤 50 ms 이상 같은 값일 때 안정된 입력으로 받아들입니다.

50 ms는 수업용 시작값입니다. 버튼에 따라 교사가 확인해야 합니다. 아주 짧은 누름은 인식되지 않을 수 있어요. 오늘은 시간 처리 코드를 모두 외우기보다 새 누름을 한 번만 인정하는 이유에 집중합니다.

전체 코드 · 상태 기억 + 버튼 튐 처리
remember_request.ino
const int LED_PIN = 23;
const int BUTTON_PIN = 18;
const unsigned long DEBOUNCE_MS = 50;

bool requestOn = false;   // 버튼을 놓아도 유지할 요청 상태
int lastRaw = HIGH;      // 직전에 읽은 원래 입력
int stableButton = HIGH; // 안정된 입력
unsigned long lastChangeAt = 0;

void setup() {
  pinMode(LED_PIN, OUTPUT);
  pinMode(BUTTON_PIN, INPUT_PULLUP);
  digitalWrite(LED_PIN, LOW);
  Serial.begin(115200);
  // 시작할 때 이미 눌린 버튼은 새 요청으로 세지 않아요.
  lastRaw = digitalRead(BUTTON_PIN);
  stableButton = lastRaw;
  lastChangeAt = millis();
  Serial.println("READY: request OFF");
}

void loop() {
  int raw = digitalRead(BUTTON_PIN);
  unsigned long now = millis();

  // 원래 입력이 바뀌면 안정 시간을 다시 측정해요.
  if (raw != lastRaw) {
    lastChangeAt = now;
    lastRaw = raw;
  }

  // 같은 값이 50 ms 이상 유지되어야 새 입력으로 인정해요.
  if (now - lastChangeAt >= DEBOUNCE_MS && raw != stableButton) {
    int previousStable = stableButton;
    stableButton = raw;

    // 안정된 입력이 HIGH -> LOW로 변한 순간에만 반전!
    if (previousStable == HIGH && stableButton == LOW) {
      requestOn = !requestOn;
      digitalWrite(LED_PIN, requestOn ? HIGH : LOW);
      Serial.println(requestOn ? "Request ON" : "Request OFF");
    }
  }
}

업로드하고 확인하기
  1. 2차시 회로를 짝과 점검한 후 USB를 연결합니다. 보드와 포트 선택은 2차시와 같습니다.
  2. 새 스케치에 전체 코드를 붙여 넣고 검증(✓) → 업로드(→)합니다. 이전 코드에 덧붙이지 않습니다.
  3. 시리얼 모니터를 115200 baud로 열고, 충분히 눌렀다가 놓아 봅니다. LED는 켜진 상태를 유지해야 합니다.
  4. 다시 눌렀다가 놓으면 꺼지는지, 3초 동안 눌러도 상태가 한 번만 바뀌는지 확인합니다.

시작할 때 이미 누르고 있던 버튼은 새 요청으로 세지 않습니다. 놓았다가 다시 눌러 보세요. 전원을 다시 켜면 requestOn은 false로 초기화됩니다.

길게 누르면 여러 번 바뀌어요

단순히 LOW인 동안 반전시키고 있지 않은지 확인하세요. HIGH에서 LOW로 바뀌는 순간만 처리해야 합니다. AI가 버튼 튐 처리나 안정된 입력 비교를 제거하지 않았는지도 확인하세요.

눌러도 반응하지 않거나 바로 꺼져요

2차시처럼 입력이 1과 0으로 바뀌는지 먼저 점검합니다. 충분히 누르고 놓은 뒤 다시 눌러 보세요. requestOn을 loop 안에서 초기화하거나, 놓을 때 LED를 무조건 끄는 코드가 남아 있지 않은지 확인합니다.

교사용 운영 · 평가 · 교육과정 정합성

45분: 문제 발견 5 → 상태 규칙 7 → 코드 실행 10 → AI 코드 탐구 10 → 짝 검증 8 → 성찰 5분. 교사는 회로와 전체 코드를 사전 확인합니다. 실제 보드 업로드·점등 검증은 별도로 필요합니다.

학습 연결: 정보 교과의 변수·조건·반복과 피지컬 컴퓨팅에 연결한 동아리 활동입니다. 핵심 개념은 입력, 변화 감지, 상태 기억이며 ‘현재 출력은 현재 입력뿐 아니라 이전에 저장한 상태에도 영향을 받는다’는 아이디어를 탐구합니다. 특정 학년 성취기준의 달성을 한 차시만으로 판정하지 않습니다.

맞춤 지원: 기본 학생은 핵심 조건과 requestOn의 역할을 설명하고, 버튼 튐 처리는 제공된 코드를 사용합니다. 빠른 학생은 취소와 접수 완료를 구분하는 상태 규칙을 설계합니다. 한 번에 상태를 늘리기보다 왜 필요한지 사용자 관점에서 설명하게 합니다.

공통 평가 준거: 입력과 요청 상태 구분, 길게 누르기·놓기·재누름 검증, AI 제안과 짝 피드백에 근거한 수정 이유를 관찰과 기록으로 확인합니다. ‘예상은? → 어떤 변수에서 증거를 찾았니? → 무엇을 다시 시험할까?’로 피드백합니다.

대구미래역량교육과정 정합성: 불편 발견과 신호 의미 선택은 자율성, 예측–실험–재시험은 주도성, 역할 교대와 공동 검증은 관계성을 반영합니다. 창의융합적 사고는 상태 변화 설명, 공감·소통은 신호 해석 비교, 자기관리는 안전·시험 기록, 공동체 역량은 실수로 취소되지 않는 사용 규칙 제안으로 관찰합니다. 목표–활동–평가를 같은 수행 증거로 연결했습니다.
